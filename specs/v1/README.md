# Wireclaw V1 Specification

Read in this order:

1. `constitution.md` — non-negotiable product principles
2. `requirements.md` — stable V1 requirement IDs and acceptance criteria
3. `solution.md` — implementable architecture and behavior
4. `tasks.md` — gated delivery sequence

Supporting design references live under `docs/`, and shared machine-readable contracts live under `contracts/`.

A material behavior change should update the specification before implementation. Do not use `tasks.md` to override requirements or constitution rules.
